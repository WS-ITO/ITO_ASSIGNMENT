2. 데이터 파일 형식

입력 파일 형식

각 줄은 주문 요청 1건이며, 4개 필드를 | 로 구분합니다.

orderId|productName|quantity|price

예) ORD001|사과|3|1500.0
    ORD002|바나나|5|800.0

저장 파일 형식

order.toFileString() 을 사용하면 아래 형식으로 저장됩니다.

orderId|productName|quantity|price|status|createdAt

예) ORD001|사과|3|1500.0|PENDING|2024-06-01T09:30:00

3. OrderService.java 구현 항목 구현 대상

OrderService.java 안의 [구현 N] 메서드 3개만 완성하면 됩니다. 나머지 메서드는 [제공] 수정 금지로 이미 구현되어 있으니 그대로 호출해 사용하세요.

번호메서드설명
[구현 1] processOrderFile(String) 입력 파일 읽기 → 파싱 → 유효성 검사 → 중복 확인 → 저장 → 반환. 대량(10만 건) 테스트가 있으므로 건별 파일 열기 대신 BufferedReader/BufferedWriter 스트리밍으로 구현
[구현 2] findAllOrders() 저장 파일 전체를 읽어 Order 리스트 반환 (없으면 빈 리스트)
[구현 3] minOrdersToFulfill(List<Order>, int) 서로 다른 묶음 수량(order.getQuantity())의 주문들을 무제한 반복 주문해 목표 수량을 정확히 채우는 최소 주문 건수. 불가능하면 -1, 목표 0이면 0. 무작정 큰 묶음부터 담으면 최소가 아닐 수 있어(예: {1,3,4}로 6 채우기 → 4+1+1 = 3건), 모든 조합을 따지는 DP로 풀어야 함 (정답: 3+3 = 2건)

제공 메서드 수정 금지

아래 메서드는 OrderService.java에 이미 구현되어 있습니다. 수정하지 말고 그대로 사용하세요.

메서드설명
생성자 OrderService(String)저장 파일의 상위 디렉토리·파일이 없으면 생성
parseInputLine(String)입력 파일 한 줄(4필드) → Order 변환
validateOrder(Order)orderId·productName 빈값, quantity < 1, price ≤ 0 검사 → InvalidOrderException
parseStoredLine(String)저장 파일 한 줄(6필드) → Order 복원
loadExistingIds()저장 파일의 기존 orderId 전체를 Set 으로 로드 (중복 확인용)
clearStorage()저장 파일 내용 비우기 (테스트 초기화 시 호출)

4. 제공 클래스 API 요약

Order 제공

생성자 / 메서드설명

5. 테스트 안내

테스트 파일: src/test/java/com/ito/order/OrderServiceTest.java

실행 명령: mvn test — 모든 테스트 통과 시 BUILD SUCCESS

번호그룹테스트 메서드검증 내용
1-1 대량 처리
(100,000건 / 10초)		 processBulkFile_completesWithinTimeout 100,000건 처리 후 반환 목록 크기 + 첫 주문 필드 값 검증 (파싱 정확성)
1-2 processBulkFile_allOrdersRetrievable 100,000건 저장 후 전체 조회 건수 + 재조회 필드 값 검증 (저장/복원 정확성)
1-3 processBulkFile_reprocess_throwsDuplicateOrderException 이미 저장된 주문을 다시 처리하면 DuplicateOrderException 발생
2-1 최소 주문 건수
(DP)		 minOrdersToFulfill_bigPackFirstFails_returnsOptimal 큰 묶음부터 담으면 틀리는 케이스도 최소 건수 반환 (묶음 {1,3,4}, 목표 6 → 2)
2-2 minOrdersToFulfill_zeroTarget_returnsZero 목표 수량이 0이면 0 반환
2-3 minOrdersToFulfill_impossible_returnsMinusOne 정확히 채울 수 없으면 -1 반환 (묶음 {3,5}, 목표 7)
2-4 minOrdersToFulfill_singlePack_returnsCount 단일 묶음으로 정확히 나눠지는 경우 (묶음 {2}, 목표 8 → 4)
